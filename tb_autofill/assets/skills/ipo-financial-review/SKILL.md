# IPO 财务核查与问询应对

## 用途

把 2800 份 A 股、新三板与港股上市申请文件（招股说明书、公开转让说明书、联交所申请版本）中沉淀的财务披露与核查实践，转化为可执行的核查方案与问询答复。核心不是复述审计准则，而是回答三个问题：**监管会问什么、凭什么证据答、答到什么程度算够**。

样本基础：主板、科创板、创业板、北交所、新三板、港股六个板块共 18 家申报企业，含 12 份关键审计事项的完整审计应对程序。

## 触发场景

- 核查设计：某科目/某业务模式的核查程序如何设计、样本量怎么定、函证与走访如何覆盖。
- 问询应对：收到审核问询函，需要拆解问题意图、组织答复框架、准备支撑材料。
- 异常解释：毛利率高于/低于同行业、收入与现金流背离、客户集中度骤变、经销收入占比高，如何论证合理性。
- 申报差异：申报报表与原始报表差异、会计差错更正、股改时点调整的处理与披露。
- 板块选择：不同板块的上市标准、科创属性/创业板定位指标、披露章节差异。
- 底稿复核：判断项目组已执行的程序是否足以支持披露结论。

不适用：替代项目合伙人签署意见、法律事项（股权清晰、同业竞争的法律定性）、行业研究本身。

## 核查总则

### 一、先定业务模式，再定核查方案

收入确认模式决定核查重点，模式不同则程序不可通用：
- 直销 vs 经销（是否买断、是否有退换货条款、经销商最终销售）
- 寄售 vs 非寄售（控制权转移时点在客户领用还是发货）
- 内销 vs 出口（报关单、提单、离岸/到岸、外销收入与海关数据核对）
- 时段法 vs 时点法（履约进度依据、成本归集、结算单取得）
- 总额法 vs 净额法（主要责任人判断，涉及收入规模与毛利率的重大差异）

同一企业可能存在多种模式并存（如北交所某改性塑料企业同时存在寄售与非寄售），必须**分模式列示收入、分模式设计程序、分模式披露客户与金额**。

### 二、证据链要求三流合一

任何一笔收入的支撑必须同时落到三条线，缺一条即为核查缺口：

| 流 | 证据 | 断点含义 |
|---|---|---|
| 合同流 | 合同/订单、价格条款、验收条款、退换货条款 | 无合同或事后补签 → 收入真实性存疑 |
| 货物流 | 出库单、送货单、签收单/验收单、报关单、提单、物流记录 | 无签收或签收人为关联方 → 控制权转移存疑 |
| 资金流 | 银行流水、收款凭证、承兑汇票、第三方回款说明 | 回款方与客户不一致 → 资金体外循环风险 |

### 三、程序分层：了解内控 → 控制测试 → 实质性程序 → 分析性复核

招股书披露的关键审计事项程序，可归纳为固定的八步（收入类）：
1. 了解并评价与收入确认相关的关键内部控制设计与运行有效性；
2. 检查主要客户合同条款及实际执行，评价收入确认政策是否符合准则；
3. 对主要客户销售额函证，调查回函不符事项，对未回函样本执行替代程序；
4. 对主要客户实地走访（或视频访谈），了解业务模式、结算方式、交易背景；
5. 抽样执行细节测试，检查合同/订单、出库单、签收单、发票、报关单、提单、银行水单；
6. 执行收入截止性测试，复核是否计入恰当期间；
7. 执行分析性复核，对收入与毛利率变动分析合理性；
8. 复核财务报表与附注中与收入相关的披露。

### 四、函证不是万能的，必须配套替代程序

- 回函率、不符事项处理、未回函替代测试是三个独立结论点，缺一不可。
- 对境外客户、经销商、关联方，函证可信度下降，须叠加走访、终端核实、期后回款检查。
- 函证金额应同时覆盖收入发生额与应收余额，并检查**期后回款**。

### 五、所有异常都要落到「可验证的解释 + 支持性数据」

监管不接受"符合行业惯例""具有商业合理性"这类结论性表述。合格的解释必须包含：
数值（差异幅度）、可比对象（同行业公司/历史期间）、驱动因素（量、价、结构）、验证方式（何种程序支持的）。

## 输出结构

```
【结论】核查是否充分/该异常能否解释，一句话给判断。
【口径】本案适用的收入确认模式、上市标准、披露要求。
【证据链】按合同流/货物流/资金流列出已具备与缺失的证据。
【程序】可执行的动作清单：对象、范围、样本、单据、判断标准。
【披露】招股书应在哪一节、以何口径披露，需量化到什么程度。
【风险与边界】监管可能追问的下一层问题、结论不成立的条件。
```

## 表述规范

- 程序写动作，不写意图：写「对前十大客户中境外客户 12 家全部实地走访，覆盖外销收入 87%」，不写「充分关注境外客户真实性」。
- 样本量给依据：按金额覆盖率（如覆盖 70% 以上）或统计抽样，说明选择理由。
- 引用依据区分强制性与参考性：审核问答、监管规则适用指引为强制性；交易所审核动态、同类案例为参考。
- 不虚构文号与案例。引用具体公司时须能在 `data/digests/` 中找到对应样本，否则改为"同类申报案例中常见做法"。

## 数据与案例

`data/digests/` 存 18 家申报企业的章节结构与财务披露摘要，按「公司名_板块.md」命名。`data/checks.md` 汇总 12 份关键审计事项的收入核查程序原文。

检索先例：

```bash
grep -l "寄售" data/digests/*.md          # 找采用寄售模式披露的案例
grep -h "毛利率" data/digests/*主板*.md    # 看主板公司毛利率分析写法
```

引用案例时注明公司与板块，并说明本案与其事实差异；不得把某家公司的处理直接当作监管口径。

## 硬性边界

- 核查结论必须与已执行程序对应；未经程序支持的事实不得写入结论。
- 涉及体外资金循环、虚构交易、关联方非关联化迹象时，在【风险与边界】中单独列示，并说明对申报可行性的影响。
- 不代替保荐机构、发行人律师与项目合伙人的最终判断；重大事项建议提交质控与技术部门复核。
