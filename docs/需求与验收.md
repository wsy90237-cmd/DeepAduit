# 需求与验收

当前产品名：DeepAudit。已实现 TB 工作台、总览及安全设置；附注与底稿目前仅有规划入口，不能作为已实现功能验收。

流程：扫描鼎信诺 → 选择项目、主体、年度和截止期间 → 导入用户模板 → 选择仅期初、仅期末或两者 → 识别和预览 → 填列或复核 → 另存。

## 必须满足

- 只读取科目余额明细；不同主体、年度和期间不能混加。
- 字段依据文字、科目层级、表头和期间定位，不能依赖固定 D/E 列或行号。
- 保留公式、调整分录、未选期间及原始文件。默认只补空，已有值必须选择覆盖。
- 明确区分账面数与审定数、余额与发生额、零值与缺失；重复及不确定匹配需人工确认。
- 报告列出来源、目标、期望值、已有值、差额、方法和原因。
- DeepSeek 使用用户自己的 Key，首次可配置，之后可更换、停用、删除；无 Key 可离线运行。
- Key 本机加密；上传 AI 的内容可预览；AI 只能建议，不能直接改变金额。
- 每轮必要检查通过后 Git 提交并推送；私有数据和凭据不提交。

## 验证场景

v0.4.0 额外验收：上下文切换使旧结果失效、旧后台响应丢弃、导出快照一致性、多层审定／调整表头保护、本月发生额缺少依据时拒填、后台异常后继续操作、输出范围外变化、日志尾部截断及检查点异常、原生发布门禁。

三种期间、插行移列、合并表头、别名、重复名称、上下级科目重复、损益结转、真实零与缺失、不同主体期间、公式保护、旧值覆盖、数据库复制期间变化、Key 管理、网络和 API 错误、非法 AI 建议、不同电脑安装与运行。

真实取数和真实 DeepSeek 验证必须单独记录，合成测试通过不能代替真实联调。
