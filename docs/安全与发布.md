# DeepAudit 安全与发布

## 保护目标与边界

本版以原生编译运行包交付，保护当前 Windows 用户保存的 API Key，并校验日志尾部完整性。原始账套仍只从一致副本读取。2026-11-02 核实源码仓库为公开状态，原生编译不提供源码保密保证；本轮没有改变仓库可见性。

任何交付到用户机器、可以独立执行的软件都可能被分析。原生编译提高代码还原成本，不能成为“无法逆向”的保证。本版不加入关闭安全软件、阻止调试器、检测虚拟机、破坏分析环境等行为。

真正必须保密的算法、授权签发密钥、共享 API 密钥应放在受控服务器。当前没有提供服务器地址或授权业务规则，因此没有虚构激活服务，也没有将共享秘密硬编码进客户端。

## 已实施

1. 正式发布由 Nuitka 编译业务模块为本机代码；不再保留旧 PyInstaller 发布配置。构建阶段拒绝业务模块未原生编译的产物。
2. 发布进程采用 Python isolated 模式，忽略外部 Python 路径与用户 site 配置，减少加载软件目录外 Python 代码的机会。该措施不是操作系统级沙箱。
3. 客户只接收 EXE、校验值、安装说明和不含本机路径的构建清单；不分发 `.py`、`.pyc`、生成的 `.c`、`.pdb`、编译报告、真实账套和日志。
4. 模型 Key 与 ima 凭证分别由当前 Windows 用户的 DPAPI 加密保存到 `connections.json`。无新文件时只读兼容旧 `settings.json`；保存不覆盖旧文件。切换模型服务须重新输入对应 Key，拒绝网络重定向，不把服务端原始错误正文写入界面或日志。
5. 日志采用进程间文件锁、现有链校验和 DPAPI 加密末尾检查点。截断末尾或删除日志但保留检查点时，校验失败，继续追加会被拒绝。
6. 所有金额仍来自本地 Decimal 计算；AI 返回白名单、已有值确认、公式保护及只读数据库副本规则保留。
7. 切换上下文使结果和提案失效；后台响应带上下文版本；导出绑定账套指纹及不可混用的任务快照。
8. ima 固定访问官方 HTTPS 接口，仅做只读检索；不下载包含临时授权头的媒体链接，不转发登录 Cookie。每次模型请求先预览资料和目的服务，知识正文缺失或引用编号错误时不能直接采用提案。

本地知识库 `knowledge.sqlite3` 保存未加密的导入文字。DPAPI 保护的是凭证，不代表知识缓存或用户同一账户中的程序不可访问。DOCX/PDF 有大小与结构限制，但文档解析器不是隔离沙箱；请使用可信资料。本版只检查引用编号，原文真实性、生效日期和结论适用性仍须人工复核。

## 日志升级与故障处理

旧日志没有检查点时，界面明确显示“仅链内校验”，不将其标为完全完整。首次成功追加会在既有有效链的末尾建立检查点；这不能补证升级前是否发生过尾部删除。

检查点受 DPAPI 完整性保护，但同一 Windows 账户有能力调用 DPAPI；若该账户同时回滚或删除日志和检查点，单机软件无法可靠发现。需要这种保证时应接入独立服务器或可信外部存证。

若日志追加后检查点保存失败，日志与旧检查点可能不一致。应用会报告失败，不继续追加；请备份原日志及检查点并人工核对。不要通过删除检查点来消除警告。输出文件若已经生成，应保留以便核对，不应把“业务完成”误当作“留痕成功”。

## 签名与分发

当前未提供代码签名证书，所以本版未签名。SHA-256 校验可以发现文件与所提供摘要不符，但摘要本身需要从可信渠道获取。数字签名能够证明发布者和文件完整性，不承担防逆向功能。

后续配置签名时，应将证书及其密码保存在受控 CI 机密或硬件密钥服务中，在构建和自检通过后签名，再生成最终 SHA-256。签名前后 EXE 哈希不同，必须以签名后的文件为准。证书不进入源码仓库或客户软件。

本版没有搭建授权系统。需要按用户、席位、期限、机器或离线使用授权时，应先确定业务规则，再将授权签发放在服务器侧；客户端只携带验证公钥。

## 维护者核验

```powershell
python -m unittest discover -s tests -v
python launch.py --selftest
python tools/build_release.py --compiler msvc --jobs 2
python tools/build_release.py --check-only dist/DeepAudit.exe
```

构建的私有 XML 报告在 `build/native-compilation-report.xml`，不随客户包分发。`BUILDINFO.json` 记录版本、源码基线、工作区是否存在未提交修改、编译器选项、原生模块检查结果和 EXE 哈希。只有干净工作区的 CI 产物才用于正式发布。

本轮依照 ponytail full 规则修改；按 REA 的包优先证据路线评估旧 PyInstaller 包。当前会话没有 REA MCP 分析工具，本机也没有 npm/npx，未擅自改写客户端配置或安装本机反编译引擎。普通 PyInstaller 归档检查、PE 读取及原生模块自检是工具自身的证据，不冒称 REA 引擎结果。

参考：[PyInstaller 对源码隐藏边界的说明](https://www.pyinstaller.org/en/stable/operating-mode.html#hiding-the-source-code)、[Nuitka 构建说明](https://nuitka.net/user-documentation/user-manual.html)、[REA 技能说明](https://github.com/morluto/rea/tree/79d2fc05405c76bc0a8f71b9c10355135da4747b/.agents/skills/reverse-engineer-anything)。
