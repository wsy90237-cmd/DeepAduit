# DeepAudit 工作空间与扩展规划

0.5.0 已实现驾驶舱、TB 工作区、模型与安全、财会知识库、报告准备清单，以及现有附注/底稿/报告的文字辅助复核。风险与程序页面展示全流程设计。附注内容生成、Word/PDF 导出、审计程序执行管理与底稿生成尚未实现。完整阶段说明见 [年度审计引擎设计](年度审计引擎设计.md)。

## 共享项目上下文

现有运行上下文包括已读取主体、年度、截止月份、科目余额记录、模板指纹、完整账套指纹和当前匹配结果。页面切换不重复取数；来源或参数改变会使 TB 结果和 AI 提案失效。

界面层在 `tb_autofill/workspace.py` 组织导航和各工作区；TB 业务继续由 fields、matching、workbook 负责。模型连接、知识检索、准备度计算分别位于 connections、knowledge、workflow。本地 SQLite 仅保存已实际导入的知识资料；尚未建立项目、底稿或证据的空表。

## 后续附注模块

建议按以下顺序落地：

1. 确定附注模板类型、会计准则、行业和输出格式，收集允许使用的合成样例。
2. 关联已确认版本的 TB，按科目或报表项目映射附注字段，区分账面、调整、审定和比较期间。
3. 为附注中无法由 TB 推导的文字和明细单独收集依据；缺少依据时保留待补充，不能让 AI 编造金额或事实。
4. 附注勾稽检查通过并人工确认后，生成一份新文件，保留模板与来源索引。

## 后续底稿模块

建议先选择一种具体底稿作为最小闭环，而不是一次覆盖所有科目。为每份底稿保存项目标识、主体与期间、底稿索引、TB 版本与指纹、程序、证据文件引用、编制人、复核人和版本。

来源 TB 或证据更新时，关联底稿标为需要重新复核；不能静默沿用旧结论。生成内容与人工审定结论区分保存。证据文件不自动上传到模型；上传范围应可预览和取消。

## 优先顺序

先确定模板和审计程序范围，再设计本地项目文件与版本关系；需要跨人协作或独立留痕时再接入权限和服务端存证。当前不创建空数据库表、不生成伪底稿、不展示尚不能工作的“生成”按钮。
