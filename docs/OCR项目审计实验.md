# 项目 PDF、OCR 与 AI 底稿实验

0.8.0 实验分支从 0.7.0 本地基线 `e184c3a` 分出。下列步骤面向 Windows 源码试用。正式安装包另按 GitHub Releases 的原生构建和 SHA-256 校验流程交付。

## 试用

1. 运行仓库中的“启动Attesta.cmd”。读取鼎信诺科目余额，核对主体、期间；如已选择 TB 模板，先完成模板识别。
2. 进入“审计底稿 → 项目 PDF 与 OCR”。选各公司共用的存放目录。软件为主体及其编号创建可读目录，按年保存。可多选 PDF 导入，也可点“打开资料夹”，将资料放入本年度“原始资料”后点“识别资料夹”。批量识别支持在当前文件结束后停止。重复导入同名同内容文件复用已识别结果。
3. 文字页直接取文字，扫描页调用本机 Windows OCR。扫描图上只有少量文字层的页面也会尝试 OCR。识别质量取决于清晰度和系统 OCR 语言组件。通过证据编号可查到具体版本和页码；选择旧版文件可以打开历史快照。
4. 打开 PDF 核对原件，再点“已核对资料归属”。归属提示比较明确标注的户名和余额日期。选中报表项目和原文，可使用“手工摘录”或“预览并请求 AI 填写建议”。模型连接沿用软件设置；预览列明服务、模型和发送内容。逐页抽取，字段值和引文须能在原文中找到。
5. 对货币资金，可在建议窗口点“核对银行账户余额”。若账套有独立的逐户银行明细，选末级科目并核实一户一科目和原币单位。若账套只有银行存款汇总，导入逐户清单；当前实验支持单一币种和单一对应汇总科目。清单换版会使旧核对结果进入待复核。
6. 差额按**银行证据余额减账面余额**计算。户名、完整账号、币种或截止日缺失或不一致时，查看待核事项。“按差额分析风险”可在预览后把核对结果交给模型，请其提出下一步程序。核实并编辑建议，填写核对人，点“已核对原件，采纳至底稿”。
7. 回到“制作报表项目底稿”，导出对应报表项目的整册 Excel。软件默认定位到本年度的“底稿”目录，已确认记录进入“证据核对与风险”工作表，目录中有对应索引。更换资料后，在项目窗口查看“已确认记录”中的待重新复核提示，重新核对并导出新版。已经另存的 Excel 保留其导出时的记录。

### 逐户余额清单

Excel 仅保留一张名为“银行账户余额清单”的工作表。第一行按顺序填写下列列名。每行一户，科目编码和完整账号用文本保存，金额单位填“元”。金额与总账使用相同币种及单位。整表科目、主体和截止日一致，合计核平后方可用于逐户比较。

## 分阶段验收

| 阶段 | 业务成果 | 验收方式 |
| --- | --- | --- |
| 一、保留基线 | 独立保留 0.7.0，实验分支运行 0.8.0 | 分别从启动入口运行离线自检 |
| 二、项目资料 | 公司、年度、证据快照、分页文字、归属提示 | 合成中英文扫描 PDF、带文字层 PDF、同名换版与跨公司隔离 |
| 三、证据核对与底稿 | 字段原值、差额、风险、后续程序与核对人进入整册 | 合成账面 120 万、回函 118 万；回读导出 Excel，核对 −2 万与证据页码 |
| 四、扩大业务范围 | 按实际复核反馈选择合同、凭证附件或往来函证作为下一类 | 先明确目标字段、独立核对依据、异常及缺证样例，再新增程序和验收集 |

本轮验证使用合成材料。外部服务请求流程使用可重复的模型响应验证；真实模型在客户资料上的字段准确率尚待单独验收。当前输出是可复核的底稿草稿，附注与报告生成继续按项目原计划推进。
