# Attesta 审计 Agent 设计

> 本文是目标设计，不表示能力已上线。第一版范围已收敛为 **M1（TB 副本与待处理清单）** 与 **M2（报表项目整册底稿）**，两者初版代码与测试已在本分支、验收中。**附注/报告草稿列为 M3 下一阶段**：`reporting.py` 虽有初版代码，但运行时未注册对应工具，界面不显示为可用交付物。未完成阶段统一标为“计划”，不得显示为可用按钮。

**章节**：1 目标 · 2 产品边界 · 3 架构 · 4 用户流程与必要确认 · 5 工具清单 · 6 安全与失败模式 · 7 测试与验收 · 8 分阶段计划与未实现项 · 9 与现有文档的衔接

## 1. 目标

把 Attesta 从“单点 AI 复核”升级为工具调用型审计 Agent：以一次受限运行为单位，从账套只读副本出发，完成 **账套 → TB → 报表项目整册底稿**，全过程可停止、可查看、可复核。附注草稿与报告草稿是下一阶段目标，不在第一版交付。

- 用户自备 DeepSeek API Key（默认 `https://api.deepseek.com`），由现有 DPAPI 设置存储加密保存在本机，Agent 不新建密钥通道。
- 金额、借贷方向、父子层级、期间与勾稽全部由本地程序计算；模型只选择来源科目、判断口径、拟写文字与提出缺口。
- 一次运行即一个快照：主体、期间、账套指纹、模板指纹与 TB 结果在启动时复制，运行中不被界面变化悄悄替换。
- 交付判据是“可追溯的草稿”，不是“已完成的审计”：产物记录来源、快照、哈希与缺口，来源变化后旧结论必须重做。

## 2. 产品边界

**第一版做：**

- 复核并另存 TB 副本、导出待处理清单；按已确认报表项目整册制作底稿草稿并导出 Excel；按知识库片段提供可核对参考。
- 只在用户确认的输出目录写入**新文件**；不覆盖原模板、原账套、原底稿；记录运行事件、产物哈希与缺口。
- 完成状态由本地程序核对产物（见 7.5），不采信模型自述的“已完成”。

**下一阶段（M3）：** 附注草稿与报告文字草稿（仅草稿、不签发），工具未注册前界面不提供入口。

**不做（固定）：**

- 不签发报告、不形成最终意见。报告意见类型由项目组确定；草稿只能标注“草稿·未签发”。
- 不修改原数据库、原模板、公式、调整分录与未选期间；读取仍走校验过的一致副本，金额全部本地计算。
- 不开放 shell、任意 SQL、任意路径或网络浏览；模型只能调用白名单工具。
- 不在本期落地：合并报表与抵消、完整风险与重要性引擎、调整分录审批流、证据自动采集与上传、团队权限、服务端存证、签发归档。
- 不承诺“本机日志不可篡改”；沿用 `README.md` 与 `docs/安全与发布.md` 的日志口径。

## 3. 架构

```text
agent_ui（启动范围确认 · 运行面板 · 确认桥 · 结果与缺口）
   │  ApprovalBridge：写文件 / 扩大范围 / 提问
   ▼
AgentRuntime（预算 · 取消 · 来源核对 · 范围复核 · 工具调度 · 事件）
   │  ToolRegistry（agent_tools.py：白名单 + 参数校验 + kind + result_scope）
   ▼
现有模块：ai · matching · papers · dxn/dxn_paper · workbook · fields · reporting（M3 未接入）
   ├─ AgentRecorder → auditlog（哈希链 + DPAPI 末尾检查点）
   └─ SettingsStore（DPAPI 加密 Key，只交给 DeepSeekClient）
```

### 3.1 分层职责

| 层 | 职责 | 现状 |
| --- | --- | --- |
| `agent_ui` | 启动对话框、事件面板、“停止”、写文件与扩大范围确认、结果与缺口展示；交付物只列 TB 与整册底稿 | 初版已有（M1/M2 验收中） |
| `AgentRuntime` | 同步循环：取模型回复、执行工具、回传结果、检查预算/取消/来源、完成核对、发事件 | 初版已有（`agent.py`） |
| `ToolRegistry` | 工具白名单、最小 JSON Schema 参数校验、工具类型、结果数据类别 `result_scope` | 初版已有（`agent_tools.py`） |
| 现有业务模块 | 取数、匹配、金额计算、底稿构建与导出；附注/报告模块为下一阶段 | 已存在（`reporting.py` 初版代码已有，未接入） |
| `ApprovalBridge` | 在后台线程与界面之间阻塞等待确认，返回结构化决定 | 初版已有（M1 验收中） |
| `AgentRecorder` | 事件与审计记录写入 `auditlog` 与本次运行记录；不含 Key、完整工作簿、原库或凭证，模型答复按文字保存 | 初版已有（M1 验收中） |

### 3.2 运行上下文

- **快照 `ProjectSnapshot`**：启动时复制主体、年度/截止月、模板路径与指纹、单位、科目余额行、模板扫描结果、TB 结果、底稿库和界面修订号。
- **工作副本 `AgentContext`**：本次运行的 rows/results/scan、输出目录、阶段、报表项目、预算、已准备底稿、`artifacts`、`gaps`，以及只来自本地已确认证据的 `evidence_rows`。
- **不变式**：工具只改工作副本；落盘只发生在 `write` 工具且必须经确认；快照版本（主体、期间、账套/模板指纹、TB 结果）变化时立即停止，不得继续写入。
- **产物记录**：`kind / path / sha256 / source / note / target`；**缺口**统一进入 `gaps`，最终写入结果面板与“待补”标注。

### 3.3 运行循环

1. 每步调用 `chat_tools`：模型返回正文与工具调用（单轮最多 8 个，参数必须是 JSON 对象且不超过 16000 字符）。
2. 运行时按白名单执行工具；**结果回传模型前按数据范围类别再次核对授权**，未授权结果丢弃并转确认或拒绝；超过 12000 字符截断并标注，截断不等于数据不存在。
3. 每步检查取消、来源与预算；同一工具连续三次以相同参数调用即停止，避免循环。
4. 调用 `finish` 结束；完成状态由本地程序核对 TB 副本、待处理清单与整册底稿是否实际存在且哈希有效（7.5），缺项显示“部分完成”。

### 3.4 确认桥与留痕

- `ApprovalRequest`：`kind=write|scope|question`，附带标题、摘要、明细、默认路径与批次键；界面返回 `ApprovalDecision(approved, path, auto_confirm_rest, note)`。
- **拒绝写文件后不得重试**：运行时把该工具加入本次运行的拒绝集合，模型收到“用户拒绝写入，本次运行不再重试该工具”，应改用不落盘方式或 `finish(status=blocked)`。
- **审计事件**：`agent_run_start / agent_tool_call / agent_tool_result / agent_write_approved / agent_write_denied / agent_run_end`。只记录工具名、类型、参数结构摘要（字符串截 160 字符、数组只记条数）、模型 ID 与 API 地址；不记录 Key、Authorization、完整工作簿、原库或凭证。
- **运行记录**：每次运行另存 `%LOCALAPPDATA%\ZSZH-TB\agent\runs\<run_id>.json`（本次配置与结果，含产物哈希与缺口）。模型最终答复与工具参数摘要按文字保存，可能含模型复述的客户信息；不保存完整工作簿、原库或凭证。写入失败如实提示，不冒充已留痕。

## 4. 用户流程与必要确认

### 4.1 启动范围确认（发请求前，一次）

| 项目 | 内容 |
| --- | --- |
| 服务与模型 | API 地址、模型 ID；Key 不在此界面回显 |
| 交付物 | **TB 副本 / 整册底稿**；附注、报告注明“下一阶段开放”，不作为可勾选交付物 |
| 报表项目 | 整册底稿涉及的报表项目索引（如 `1-010`）；勾选整册底稿时必须填写，未勾选则仅做 TB |
| 数据类别与数量 | 当前按交付物推导类别并列出；逐类取消与条数/字符数细分待后续实现 |
| 预算 | 步数、工具调用、模型请求次数 |
| 输出目录 | 默认写入根目录；用户可在确认框另选，勾选“同类写入自动确认”后沿用首次选择目录 |
| 可选 | 关注点（文本）、重要性说明（仅文字提示，不构成重要性引擎结论）、TB 后暂停（第一版未接） |

取消确认则不发送任何请求。运行面板显示当前服务、模型与请求事件；逐类计数、剩余预算和逐类取消待后续实现。

### 4.2 运行中三类必要确认

1. **TB/底稿写入确认**（已实现）：`export_tb_copy` / `export_workpaper` 执行前显示将写入字段数、允许覆盖数、待处理项、写入示例（或底稿证据条数与是否含模型文字）、默认输出；用户在确认框选路径。默认只补空与已确认来源；拒绝后同一工具不被重试。
2. **扩大发送范围确认**（已实现）：工具声明或返回值需要启动确认之外的类别（`ScopeError`），弹窗列明新增类别；拒绝则取消该次请求，不静默扩大。工具结果回传前还会再次核对（7.5②）。
3. **完成核对**（已实现，本地程序）：`finish` 前核对 TB 副本、待处理清单、按 `report_indexes` 的整册底稿是否存在且 SHA-256 有效；缺项把“done”降级为“部分完成”并列出缺口，产品不因模型自称完成而显示完成。

### 4.3 可选 TB 后暂停

`pause_after_tb=True` 时，TB 副本成功后暂停，等待项目组查看后再继续；`False` 时在预算内连续执行，写文件仍逐次确认。第一版只预留开关、未接界面交互；暂停不改变已发送数据范围。

### 4.4 `ask_user` 的使用边界

只用于**重大歧义**：报表项目口径、来源冲突如何取舍、是否需要扩大范围获取资料、是否将某份材料纳入本次任务。不用于日常确认（写文件与范围走确认桥），不得反复询问同一问题，不得用提问代替读取事实。用户取消回答即停止本次运行。

### 4.5 停止与取消

随时可停止：运行时置取消标志，当前工具返回后终止，未完成的写文件不再发生；已导出文件与事件保留，状态记为 `cancelled`。关闭窗口等同停止，并提示已生成的草稿路径。

## 5. 工具清单

第一版注册且可调用的工具如下（共 14 个）：

| 工具 | 类型 | 作用 | 底层实现 | 写入与限制 |
| --- | --- | --- | --- | --- |
| `get_project_context` | read | 项目摘要与阶段状态（主体、期间、模板名、单位、科目/字段数、待处理数） | 运行快照 + `matching` 统计 | 只含摘要与少量待处理项 |
| `search_accounts` | read | 按编码、名称、路径检索科目 | 快照科目行过滤 | 返回命中数与截断标志，不返回全表 |
| `get_account_facts` | read | 取指定科目的本地事实（期初、借贷、期末、父子、同名） | 快照科目行本地聚合 | 金额本地读取，含截取说明 |
| `scan_template` | compute | 本地扫描模板并执行规则匹配，返回字段、期间、单位、公式与保护标志摘要 | `fields.scan_template` + `matching` | 只读，不重算不写入；金额不发送 |
| `get_tb_status` | read | 匹配结果统计、待处理字段、差异与保护字段 | `matching` + `workbook` | 只读，金额按本地结果 |
| `run_tb_ai_fill` | model | 对疑点批量给出“填/留待/不填”与来源科目 | `ai.review` / `ai.tb_draft_batches` | 只返回决策；金额由 `matching` 计算 |
| `stage_tb_sources` | compute | 把已确认来源暂存到工作副本（内存），供后续写入 | `matching.apply_ai_suggestions` | 不落盘，不改快照，不改原模板 |
| `export_tb_copy` | write | 另存 TB Excel 副本并重算、检查平衡，导出待处理清单 CSV | `workbook.write_results` / `export_report` | 经确认；只写新副本；原模板只读 |
| `list_report_projects` | read | 列出报表项目及整册科目范围 | `papers.report_scope` | 整册口径，不合并不同账套/期间 |
| `prepare_workpaper` | model | 读取整册科目与序时账，组装底稿事实并拟写专项表建议/审计说明 | `papers.pack_request` / `paper_pack` / `dxn.read_paper_data` | 需序时账；文字核对不通过时保留本地事实 |
| `export_workpaper` | write | 导出整册底稿 Excel 草稿 | `dxn_paper.build` | 经确认；使用已确认 `evidence_rows`；不覆盖原文件 |
| `search_knowledge` | read | 内置知识库与 skill 检索，返回 `[K#]` 片段 | `skills.search` | 只读；引用编号仅限本次返回 |
| `ask_user` | user | 就重大歧义向用户提问并等待 | 确认桥 | 取消即停止；不得代替事实读取 |
| `finish` | user | 结束运行，给出状态、摘要、产物与缺口 | 运行时（含本地完成核对） | 不写文件；不得声称已完成审计或已签发 |

**M3 未注册工具**（不得调用、界面不显示入口）：`prepare_notes_draft`、`prepare_report_draft`、`export_document`。其中 `reporting.py` 初版代码已存在，但第一版注册表不包含，验收通过前不开放。

**通用规则：**

- 参数校验先于执行：强制 `additionalProperties=false`、字符串长度上限；不接收任意路径、SQL、命令或 URL。
- 返回与参数上限：`search_accounts` ≤50 条、`get_account_facts` ≤10 个科目、`stage_tb_sources` ≤20 个字段、`run_tb_ai_fill` 每批 ≤20 个字段、`search_knowledge` ≤5 条、`get_tb_status` ≤100 项；超出即截断并标注。
- 结果范围：每个工具声明 `result_scope`（`ledger/tb/journal/workpaper/knowledge`），运行时在结果进入下一轮模型请求前核对启动授权；未授权即失败并提示扩大范围，不把数据发给模型。
- `read` / `compute` 不改持久状态；`model` 只产生文字与决策候选；`write` 只写用户确认过的新文件；`user` 只与用户交互。
- 写文件名由模型建议、路径由用户在确认框选定；同名文件已存在时需再次确认，不允许静默覆盖。
- 阶段裁剪注册：第一版只注册 TB、整册底稿与只读工具；附注/报告工具在 M3 验收前不注册。

## 6. 安全与失败模式

### 6.1 数据范围类别

| 类别（授权键） | 内容 | 第一版发送规则 | 数量上限示例 |
| --- | --- | --- | --- |
| A 项目摘要（ledger） | 主体、年度/期间、模板名、单位、科目与字段计数 | 启动确认后发送 | 少量 |
| B 科目余额与层级（ledger） | 编码、名称、路径、方向、期初/期末、发生额、辅助核算 | 启动确认时勾选 | 按范围，超出标截取 |
| C TB 字段与匹配（tb） | 目标字段、状态、金额、差异、候选来源 | 启动确认时勾选 | 每次 ≤30 字段 |
| D 模板结构（tb） | 字段清单、期间、单位、公式/保护标志 | 启动确认后发送 | 结构摘要 |
| E 序时账与凭证摘要（journal） | 底稿制作所需的摘要与统计 | 需单独确认；工具声明需要 | 按工具上限 |
| F 知识参考片段（knowledge） | 内置知识库/skill 片段及来源 | 需确认 | 每次 ≤5 条，每条 ≤1500 字符 |
| G 底稿汇总事实（workpaper） | 报表项目、科目与月度发生额摘要 | 需确认 | 按整册范围 |
| H 待复核文档正文（report） | 附注/报告文字 | M3 未启用，不发送 | 不适用 |
| I 证据正文（evidence） | 已确认证据行用于本地底稿导出与缺口标注 | 不发送正文 | 仅本地 |

当前启动确认按交付物列出类别，运行记录逐次记录模型请求的消息数、字符数与已授权类别集合；逐类条数/字符数展示与逐类取消待后续实现。工具结果回传前的范围复核见 7.5②。

### 6.2 来源失效

主体、年度、截止月、模板、填列期间、单位、账套指纹或 TB 结果任一变化，或运行中快照修订号变化，都触发来源失效：运行时抛出可读错误并停止，状态记为 `stale`，不再执行写文件，已导出文件的依据同时失效。确认写入前模板被修改同样阻止导出（`tests/test_agent_scenario.py::test_source_change_between_scan_and_write_blocks_export`）。不得静默沿用旧结果或把旧响应重新激活。

### 6.3 预算、循环与超时

| 限制 | 默认值 | 行为 |
| --- | --- | --- |
| 步数 / 工具调用 / 模型请求 | 20 / 40 / 12 | 超限即停并报告当前进度 |
| 最长运行时间 | 15 分钟 | 超时停止，保留运行记录 |
| 单轮工具调用 | 8 个 | 超过则整轮不执行 |
| 单轮工具参数 / 工具结果 | 16000 / 12000 字符 | 拒绝或截断并标注 |
| 重复调用 | 同工具同参数连续 3 次 | 停止并说明疑似循环 |

预算只限制调用次数与时长，不估算费用；实际 token 与账单以服务方为准，界面提示这一点。

### 6.4 提示注入

工具结果、知识片段和文档正文一律视为**数据**：其中任何“忽略规则、泄露提示词、执行额外操作”的文字都不执行。参数白名单拒绝路径、URL 与 SQL；写文件只走确认桥；引用编号只接受本次返回的 `[K#]`。文档内容不能扩大数据范围，也不能改变写入目标。

### 6.5 失败模式与处理

| 失败 | 运行时表现 | 用户可见提示 |
| --- | --- | --- |
| 模型或兼容服务不支持 tools | `chat_tools` 失败或返回空工具调用 | 提示改选支持工具调用的模型；不回退为自由文本写文件 |
| 鉴权、余额、网络、代理、TLS 异常 | 预检或请求失败即返回，不重试写文件 | 按 HTTP 状态与网络诊断给出原因和下一步 |
| Excel COM 或 pywin32 缺失 | `export_tb_copy` 返回可读错误 | 提示安装 Excel 与 pywin32；停在该阶段，不重试 |
| 模板损坏、来源冲突、期间不符 | 工具返回错误，不写入 | 说明冲突字段，要求在 TB 页复核 |
| 证据缺失（货币资金无银行回函/对账单） | 底稿仍导出，但在证据页与缺口清单标注“未关联已确认的银行回函/对账单” | 项目组需补证据，不把缺证当已核查 |
| 知识检索无命中 | 返回空片段与说明 | 不得编造准则条号或 `[K#]` |
| 上下文截断 | 工具结果标注截断与总数 | 不得把未发送内容推断为不存在或为零 |
| 用户停止、关闭窗口 | 状态 `cancelled` | 保留已生成文件与运行记录 |
| 工具抛出未知异常 | 返回异常类型，不含栈与凭证 | 提示运行记录位置，本次不写文件 |

### 6.6 凭证与日志

### 7.5 第一版已实现的验收口径

1. **完成状态由本地核对**：`AgentRuntime._completion_gaps()` 核对本次勾选交付物——TB 副本存在、待处理清单存在、按 `report_indexes` 的整册底稿存在且 SHA-256 有效；模型 `finish(done)` 不会直接采信，缺项自动降级为“部分完成”。测试：`tests/test_agent.py::test_model_done_is_downgraded_when_required_artifacts_missing`、`::test_local_artifacts_make_done_status`。
2. **工具结果回传前复核数据范围**：`_execute` 依据工具 `result_scope` 或结果 `_scope` 调用 `ensure_scope`，未授权时结果被替换为失败提示，不进入下一轮模型请求。测试：`tests/test_agent.py::test_tool_result_scope_is_checked_before_sending_to_model`（本地查到序时账摘要但未授权 `journal`，`journal-secret` 不出现在下一轮消息）。
3. **整册底稿使用已确认证据**：`export_workpaper` 使用 `context.evidence_rows`（取自本地已确认证据）；`1-010` 货币资金无证据时写入缺口并在底稿证据页标注“未关联已确认的银行回函/对账单”，仍出草稿但不冒充已取得证据。测试：`tests/test_agent_scenario.py::test_tb_and_money_fund_workpaper_end_to_end`（断言缺口含“银行回函/对账单”、模板字节不变）。
