## 需要修复的四项

### R1 · P1：同编码换科目仍自动填入旧科目的上期数

- 位置：`tb_autofill/dxn.py:608–611`，`_paper_occurrences()`。
- 触发：本期 `660201` 为“办公费”，上年同编码为“差旅费”，均为借方。
- 实际：仅按编码和方向匹配，自动填入上年差旅费发生额 `90`，并标为同账套上年同期发生额。
- 应有行为：科目身份/层级归属不一致时，上期金额与月份保持未知，给出对应关系待确认提示；只有已证明或明确确认的跨年映射才能填入。
- 修复范围：总额和上期月份共用同一身份判定；不要仅阻止总额却继续发送/导出错误月份。年度汇总回退也不能绕过已经发现的身份冲突。名称规范化可以消除空白和分隔符差异，不能自动认定两个业务科目相同。

### R2 · P1：已确认的共享坏账准备二级类别无法进入实际取数

- 位置：`tb_autofill/dxn.py:457–460`；调用来自 `tb_autofill/gui.py:419–423`。
- 触发：共享 `1231 坏账准备=20`，下设已明确归属的应收账款准备 `123101=12`、其他应收款准备 `123102=8`，与总根勾稽一致。
- 实际：`papers.report_scope()` 正确返回应收账款 `1122` 和准备类别 `123101`，GUI 将这两个编码传给读取器；读取器要求所有编码 `level==1`，立即抛出“报表项目必须明确绑定当前账套的一级科目”。预览、AI 建议和导出都会在读取阶段被阻断。
- 应有行为：允许经过确认的报表组件子树进入同次一致副本取数，输出仅属于本报表项目的组件与明细。
- 修复范围：不能简单删除级次校验，或将整根 `1231` 塞入应收账款来绕过。需保留总根与全部类别的验证，防止同根多类别跨册重复扣减；范围验证与读取器契约应一致。补实际 GUI→读取器的集成测试，避免再次只测试已经构造好的 `PaperData`。

### R3 · P1：损益核对没有覆盖实际导出的末级明细

- 位置：`tb_autofill/dxn_paper.py:197–220` 与 `:463`；关联说明 `tb_autofill/paper_pack.py:200–203`。
- 触发：管理费用一级独立发生额 `100`，二级办公费也是 `100`，二级下三级文具费仅 `90`。
- 实际：发生额明细表列示末级三级的 `90`；`consistency()` 仅比较一级和直接二级，返回 `(True, 0)`。本地核对/AI `book_check` 可声称相符，基础说明还写成期初、借方、贷方、期末四栏已核对一致。Excel 的另一处差异公式不能抵消这个错误的核对结论。
- 应有行为：对实际导出的明细总体及其汇总层逐级核对，报告 `10` 的差异。缺任一必要发生额时保持未知；不得把缺值当零或跳过后返回相符。
- 修复范围：明确损益实际核对了本期发生额、上期发生额或月份中的哪些栏，说明文字与执行范围一致，不宣称核对未执行的四栏。测试至少覆盖三级不平、末级缺数、反向发生额、正常多层相符。

### R4 · P2：取消序时账勾选后仍导出缓存凭证

- 位置：`tb_autofill/gui.py:634` 与 `tb_autofill/dxn_paper.py:979–980`。
- 触发：先勾选“含序时账明细”读取或生成草稿，再取消勾选并导出；`PaperData` 已缓存凭证。
- 实际：GUI 传入 `journal=None` 表示排除，但 `build()` 又从 `paper_data.journal` 自动回填。合成摘要 `SYNTHETIC-EXCLUDED` 实际出现在生成文件“抽凭表”`D8`。
- 应有行为：未指定序时账与明确排除序时账必须能区分。取消后抽凭、截止性及其他附表不应带出缓存凭证；重新勾选时仍可按已确认的完整范围使用。
- 修复范围：补界面上“勾选→取消→导出→重新勾选”的测试，检查实际生成工作簿内容，不能只检查传参。
