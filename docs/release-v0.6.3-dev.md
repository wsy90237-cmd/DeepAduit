# DeepAudit 0.6.3 开发预览

本轮仍为本地开发候选，未推送、未发布，也未替换用户正在使用的 0.6.2 安装目录。

- 底稿改为按**报表项目整册**归集与导出：一册包含该项目在账套中归集的全部科目及其明细。货币资金含库存现金、银行存款、其他货币资金；固定资产含原值、累计折旧及对应减值准备；无形资产含原价、累计摊销及减值准备。科目树只用于查看，点击现金或二级明细不再缩小出册范围。
- 审定表与明细表按原模板“报表项目借贷”的乘数决定列示方向；贷方备抵科目按其真实方向参与净额，不把每个根科目先转成正数再相加。
- 往来明细按账套中实际选中的客商核算维度列示名称与期初、发生、期末，不叠加项目、部门、人员等维度；同名不同编码不合并，辅助与总账的差异单独保留。
- 损益明细表列示 1—12 月发生额以及本期、上期发生额，只使用独立发生额来源（`c_kmyek.fse`、`c_cwkmk.ws_fse/sn_ws_fse`），不把本期借方、贷方累计额或结转后余额改名充数；未取得的月份留空。
- 共享坏账准备按明确的应收类别分派，总根与其子类不一致、类别缺失或方向不明时停止归入本项目，不再整根计入应收账款。
- 新增报表项目模板目录（`tb_autofill/assets/dxn-templates.json`）：按报表项目查询候选工作表、用表规划上下文和原模板参考栏目；参考表明确标注未知取数与资料待补，不冒充已实现的专用程序。
- AI 事实中增加月度发生额、客商明细、辅助核对与来源警告；发送前仍先预览范围与目的服务，本地来源路径、表名和指纹不进入模型请求。
- 开发包随包携带空白模板原件（`templates/<标准>/originals`），逐个文件比对 `ORIGINALS.sha256` 后汇总为 `templates/TEMPLATES.sha256`，清单哈希写入 `BUILDINFO.json`，不依赖原软件安装路径。

未完成或未验证的部分：附注与报告生成仍不可用；原程序外部函数（如 `报表项目借贷`、`取报表项目数`）的内部算法未取得，模板公式仍保留未解析项；开发与测试只用合成数据，尚未在真实账套上做业务验收。正式客户 EXE 仍使用 Nuitka 原生编译，本轮未编译。
