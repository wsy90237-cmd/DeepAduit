## 二、DeepSeek 真实接口

| 项目 | 结果 |
|---|---|
| `GET /models` | HTTP 200 |
| 账户可用模型 | `deepseek-flash`、`deepseek-v4-pro` |
| `POST /chat/completions`（含 `thinking:{"type":"disabled"}`） | HTTP 200，`finish_reason = stop`，无 `reasoning_content` |
| 省略 `thinking` 参数（对照） | HTTP 200，但返回体含 `reasoning_content`，推理 token 挤占 `max_tokens`，提高 JSON 截断风险 |
| 本地结构校验 | 通过（`summary` 为字符串、`suggestions` 为数组） |

结论：保留 `thinking: {"type": "disabled"}`；模型的可用性以 `/models` 为准，代码内只保留兜底候选。

### 真实调用中的行为观察

用合成科目与 4 个目标字段（含同名歧义、币种限定、汇总行）请求复核，AI 返回空建议并给出拒绝理由：

> 「其他」存在多个同名候选（管理费用/其他、财务费用/其他），仅凭名称无法确定科目路径，不建议匹配；
> 「银行存款（美元）」在候选中仅有「银行存款」总账科目，无美元明细，名称不能证明对应关系，不建议匹配。

第二次以「房租租金支出」对「管理费用/房租」「销售费用/租金」请求复核，同样返回空建议（目标未标明父科目）。

这符合需求「名称不能证明时不建议匹配」。AI 建议被采纳的分支（选择来源后由本地重算金额、拒绝公式列与范围外科目）由 `tests/test_ai.py` 的离线用例覆盖，尚未取得真实接口下产生非空建议的样本。

## 三、合成链路端到端

模板：`tests/fixtures/试算平衡表-合成.xlsx`（虚构数据，24 个字段，单位元）。
账套：10 条合成科目记录。

| 环节 | 结果 |
|---|---|
| 模板识别 | 24 个字段，单位「元」；`期末审定数`、`调整分录`、`索引号` 列被正确排除 |
| 公式识别 | `试算平衡表!D15` → `=SUM(D4:D14)`，状态「公式保护」 |
| 默认只补空 | 预勾选 18 项；`未分配利润` 期末已有 700,000 未勾选，差额 23,000 |
| 缺失不计零 | `预收款项` 期初状态「缺少依据」，金额为空 |
| 未匹配不猜测 | `存货` 两行均为「未匹配」，未归入「其他」 |
| 写入 | 18 个字段写入，Excel 重算后逐格比对通过 |
| 覆盖保护 | 输出文件 `D14` 仍为 700,000（未覆盖） |
| 公式保护 | 输出文件 `D15` 仍为 `=SUM(D4:D14)` |
| 原模板 | 取数前后 SHA-256 摘要一致 |
| 复核报告 | CSV 25 行（1 表头 + 24 字段） |
