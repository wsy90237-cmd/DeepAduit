# Attesta 0.9.0：审计 Agent（第一版）

本版把现有 AI 补配与底稿能力接入受限工具调用型 Agent，先交付两条闭环：

1. 账套 → TB 副本 + 待处理清单；
2. TB/账套 → 报表项目整册底稿。

附注草稿与报告草稿仍为下一阶段，界面不显示可用的生成入口。

## 一、Agent 能做什么

- 导航收敛为「工作台 / 审计 Agent / 底稿 / 附注 / 报告 / 设置」；工作台负责账套、主体、期间和 TB 模板准备，TB 作为当前数据状态与 Agent 产物出现。
- 工作台的 Excel 模板只用于制作 TB 副本；整册底稿使用程序内置的鼎信诺式底稿模板，只做底稿时不需要选择 TB 模板。
- 在「审计 Agent」页直接输入任务（如“复核 2025 年 TB，重点看货币资金”）；交付物、报表项目索引、关注点、重要性和输出目录集中在「任务范围」弹窗，页面不再常驻字段说明。勾选整册底稿时必须填写报表项目索引（如 `1-010`）。
- 启动时一次确认目的服务、模型、发送数据类别与数量、预算、输出目录和写入边界；之后本地扫描、规则匹配、AI 补配不再逐次弹窗。对话流显示计划、工具调用、确认与缺口；右侧固定显示本次任务状态、产物、SHA-256 和缺口。
- 写文件前逐次确认：TB 副本会显示将写入字段数、覆盖数、待处理数、默认输出路径与写入示例；整册底稿会显示报表项目、是否含模型文字、已关联证据数和默认路径。
- 运行时间线显示工具调用、结果、确认和缺口；产物列出路径与 SHA-256。
- 完成状态由本地程序核对 TB 副本、待处理清单和 `report_indexes` 对应的整册底稿是否实际存在且哈希有效。模型返回 `finish(done)` 不会直接采信；缺项显示“部分完成”并列出缺项。
- 工具结果回传模型前按启动确认的数据类别再次核对授权；未授权的序时账等结果不会进入下一轮模型请求。
- 整册底稿使用项目中已确认的 `evidence_rows`；货币资金没有已确认银行回函/对账单时，在底稿证据页和缺口清单标注，不静默视为已核对。

## 二、安全边界

- 金额仍由本地 `matching`/`workbook`/`dxn_paper` 计算；模型只选择来源、写文字、提建议。
- 不修改原账套数据库、不覆盖原模板；所有输出另存新文件。
- 不开放 shell、任意 SQL、任意路径写入；写文件只能由确认弹窗选择。
- 来源（主体、期间、账套、模板）变化时停止后续写入，旧结果不发布。
- 报告不自动签发；附注/报告草稿为 M3 下一阶段。
- API Key 继续用 Windows DPAPI 保存在本机，不进入 Agent 上下文或运行记录。

## 三、验证范围

已用合成账套、合成模板和模拟模型响应验证：

- TB 副本 + 待处理清单 + 货币资金整册底稿端到端；
- 一个归属不明科目留待复核；
- 缺失银行回函时产生证据缺口；
- 确认写入前模板/来源变化阻止旧结果写入；
- 工具结果未授权时不进入下一轮模型请求；
- 模型声称完成但交付物缺失时降级为“部分完成”；
- 真实 `dxn_paper.build` 写出“证据核对与风险”页，证据行可回读；
- 真实 App + 脚本化模型的桌面冒烟：TB-only 产物与原模板不变，空 `report_indexes` 降级 partial；
- 独立复核发现的 M1–M5、M7、L1 已修复；M6/L6/L9 已补请求审计、finish schema 与路径最小化。

定向测试 `tests.test_agent*`、`tests.test_ai*`、`tests.test_reporting`、`tests.test_brand` 共 119 项：118 项通过，1 项“真实 Excel COM 写入与重算”在 DSH 沙箱下跳过。Excel COM 可启动，但无法新建/打开工作簿（`-2147352567`）。`tools/qa/agent_excel_probe.py` 在沙箱内输出“未执行”并返回 2，不伪造通过；需在无沙箱的本机会话重跑以取得真实重算证据。

真实 DeepSeek 请求、桌面真实 Excel 重算、正式发布 EXE 仍需在本机账户与真实环境中验证；合成测试不能替代这些联调。
