# Attesta 0.9.0：审计 Agent（第一版）

本版把现有 AI 补配与底稿能力接入受限工具调用型 Agent，先交付两条闭环：

1. 账套 → TB 副本 + 待处理清单；
2. TB/账套 → 报表项目整册底稿。

附注草稿与报告草稿仍为下一阶段，界面不显示可用的生成入口。

## 一、Agent 能做什么

- 在「审计 Agent」页选择交付物（TB 副本、整册底稿），填写可选任务目标、报表项目索引、关注点、重要性、输出目录。
- 启动时一次确认目的服务、模型、发送数据类别与数量、预算、输出目录和写入边界；之后本地扫描、规则匹配、AI 补配不再逐次弹窗。
- 写文件前逐次确认：TB 副本会显示将写入字段数、覆盖数、待处理数、默认输出路径与写入示例；整册底稿会显示报表项目、是否含模型文字、已关联证据数和默认路径。
- 运行时间线显示工具调用、结果、确认和缺口；产物列出路径与 SHA-256。
- 完成状态由本地程序核对 TB 副本、待处理清单和 `report_indexes` 对应的整册底稿是否实际存在且哈希有效。模型返回 `finish(done)` 不会直接采信；缺项显示“部分完成”并列出缺项。
- 工具结果回传模型前按启动确认的数据类别再次核对授权；未授权的序时账等结果不会进入下一轮模型请求。
- 整册底稿使用项目中已确认的 `evidence_rows`；货币资金没有已确认银行回函/对账单时，在底稿证据页和缺口清单标注，不静默视为已核对。

## 二、安全边界

- 金额仍由本地 `matching`/`workbook`/`dxn_paper` 计算；模型只选择来源、写文字、提建议。
- 不修改原账套数据库、不覆盖原模板；所有输出另存新文件。
- 不开放 shell、任意 SQL、任意路径写入；写文件只能由确认弹窗选择。
- 来源（主体、期间、账套、模板）变化时停止后续写入，旧结果不发布。
- 报告不自动签发；附注/报告草稿为 M3 下一阶段。
- API Key 继续用 Windows DPAPI 保存在本机，不进入 Agent 上下文或运行记录。

## 三、验证范围

已用合成账套、合成模板和模拟模型响应验证：

- TB 副本 + 待处理清单 + 货币资金整册底稿端到端；
- 一个归属不明科目留待复核；
- 缺失银行回函时产生证据缺口；
- 确认写入前模板/来源变化阻止旧结果写入；
- 工具结果未授权时不进入下一轮模型请求；
- 模型声称完成但交付物缺失时降级为“部分完成”。

真实 DeepSeek 请求、桌面 Excel 重算、正式发布 EXE 仍需在本机账户与真实环境中验证；合成测试不能替代这些联调。
