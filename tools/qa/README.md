# 质量核对工具（本机运行，不上传任何客户数据）

将已填 TB 作为待核对样本，隐藏非公式原填数后再匹配、事后比较。原填金额不自动视为正确答案，不参与来源选择；可比一致、差额、原填空白和证据不足分别记录。结果与缓存保存在被忽略的 `local-data/qa/`，不在源码目录保存客户资料。

| 脚本 | 用途 |
|---|---|
| `per_file_check.py <目录>` | 逐家核对：读鼎信诺账套（按项目分组、批量读库、复合键缓存）→ 识别模板 → 逐格对答案 → 输出 JSON/Markdown 清单 |
| `compare_answers.py` | 与原填数逐格比较，区分可比一致、差额、未可靠取数、原填空白及公式保护 |
| `eval_ai_review.py <序号>` | 默认只保存发送预览；人工核对范围、目的服务后，用 `--approve-preview <SHA256>` 批准相同预览。可用 `--plan` 和 `--ledger` 指定本机资料 |
| `crosstest.py` | 检查引擎复算、写入一致性及相同语义/来源范围下折算为元的跨模板冲突；引擎复算不是独立审计证据 |

约定：
- 答案列大量是公式，必须用 `data_only=True` 取缓存值比对，否则会把公式当"非数值"。
- 金额为 0 且目标格为空白时不写入（答案语料里空白通常表示无此项）。
- 期初"上期审定数"必须有审定来源，账面期初不能替代。
- 金额容限统一为 0.005 元；不同单位不能直接按显示数字比较。
- 缓存保留科目层级、主体、期间、账套、审定口径及损益标志。逐家脚本每次重新读一致副本；同名多个主体不选第一项。
- 历史默认计划与服务路径需要本机存在；诊断结果不代表已完成主体、期间、审定来源或分类证据核查。发布验证仅使用合成资料。
